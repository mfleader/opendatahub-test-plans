# TC-E2E-005: Release gate: configgen golden fixture for pgvector includes persistence and passes

**Objective**: The operator build under test carries the `cmd/configgen` golden fixture for
pgvector with the `persistence` block, and the configgen test passes.

**Falsifiability**: reverting either `provider.go` or the golden file to `be51587` makes the
configgen test fail.
**Preconditions**:

- A checkout of the operator repository
  [ogx-ai/ogx-k8s-operator](https://github.com/ogx-ai/ogx-k8s-operator), Go module path
  `github.com/ogx-ai/ogx-k8s-operator` (`go.mod`), at branch
  `fix/rhaieng-6374-pgvector-persistence`. Once the fix merges, use the merge commit or the first
  tag containing it
- Go toolchain matching the repository's `go.mod` (the Makefile pins `GOTOOLCHAIN=go1.25.8+auto`)

**Test Steps**:

1. Print `.providers.vector_io[0].config.persistence` from
   `cmd/configgen/testdata/p1-pgvector-config/want-config.yaml`
2. Print `.spec.providers.vectorIo.remote.pgvector[0].host` from that directory's `cr.yaml`
3. Run `go test ./cmd/configgen/... -run 'TestRun/p1-pgvector-config' -v`
4. Run `go test ./cmd/configgen/... -run TestRun -v`

**Expected Results**:

- Step 1 prints `backend: kv_default` and `namespace: vector_io::pgvector`. The fixture's CR omits
  `id`, and the namespace falls back to `pgvector`, the value every shipped base config uses,
  rather than to the derived provider id `remote-pgvector`
- Step 2 prints `pgvector.example.com`
- Step 3 output contains `--- PASS: TestRun/p1-pgvector-config` and ends with `ok`
- Step 4 ends with `ok` and contains no `--- FAIL` lines
