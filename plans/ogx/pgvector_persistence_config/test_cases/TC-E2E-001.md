# TC-E2E-001: Declarative pgvector CR emits the persistence block in the generated ConfigMap

**Objective**: Applying an `OGXServer` CR with `spec.providers.vectorIo.remote.pgvector` makes the
operator emit `persistence: {backend: kv_default, namespace: vector_io::pgvector}`.

**Falsifiability**: reverting `expandPgvectorProvider` to `be51587` removes the `persistence`
key, so step 5 fails.
**Preconditions**:

- Environment per Section 3.1 of the plan
- ConfigMap `ogx-base-config` (key `config.yaml`) in `ogx-pgvector-test`, labelled
  `ogx.io/watch: "true"`, holding the `starter-config-configmap.yaml` shape with
  `storage.backends.kv_default` and an `inference` provider. The `kv_default` and `sql_default`
  `db_path` values must resolve under the PVC mounted at `/.ogx`, for example
  `${env.SQLITE_STORE_DIR:=/.ogx}/kvstore.db`. The sample's default,
  `~/.ogx/distributions/starter`, resolves outside it (Section 8, risk 2)
- Secret `postgres-secret` (key `password`) in the same namespace, labelled for watch, holding a
  synthetic test password

**Test Steps**:

1. Apply the `OGXServer` CR from Test Data
2. Wait 120s for condition `ConfigGenerated=true` on `ogxserver/ogxserver-rh`
3. Read `status.conditions[*].reason`
4. Read the generated ConfigMap name from `status.configGeneration.configMapName` and confirm
   that ConfigMap exists
5. From that ConfigMap's `config.yaml`, isolate the `providers.vector_io` entry whose
   `provider_type` is `remote::pgvector`
6. List every `providers.vector_io[].provider_id` and the length of that list
7. Print `storage.backends` from the generated `config.yaml`

**Expected Results**:

- Step 3 contains `ConfigGenerationSucceeded` and not `ConfigGenerationFailed`
- Step 4 returns a non-empty ConfigMap name that exists in `ogx-pgvector-test`
- Step 5 has `provider_id: pgvector`, `provider_type: remote::pgvector`, and a
  `config.persistence` map of exactly `backend: kv_default` and `namespace: vector_io::pgvector`
- Step 5 keeps `host: postgres`, `port: 5432`, `db: postgres`, `user: postgres`, and
  `password: ${env.OGX_PGVECTOR_PASSWORD}`
- Step 6 prints one provider id, `pgvector`, and a length of `1`. The base-config `vector_io`
  entries are gone (Section 8, risk 1)
- Step 7 lists a `kv_default` entry, so the emitted `persistence.backend` resolves rather than
  dangling
