# TC-E2E-006: Release gate: pkg/config unit test asserts the pgvector persistence block

**Objective**: The operator build under test carries `pkg/config` unit tests asserting the
pgvector `persistence` block for a derived id and an explicit id, and asserting that two pgvector
providers on one OGXServer get different namespaces, and they pass.

**Falsifiability**: step 2 is the check. It reverts `provider.go` to `be51587` and requires the
unit tests to fail.
**Preconditions**:

- All preconditions of TC-E2E-005
- A clean working tree, since step 2 restores `provider.go` with `git checkout HEAD`

**Test Steps**:

1. Confirm `func TestExpandProviders_PgvectorPersistence` and
   `func TestExpandProviders_PgvectorPersistence_DistinctNamespacesPerInstance` exist in
   `pkg/config/config_test.go`
2. Revert the source under test and confirm the unit test catches it:
   `git checkout be51587 -- pkg/config/provider.go`, rerun step 3, then restore with
   `git checkout HEAD -- pkg/config/provider.go`
3. Run `go test ./pkg/config/... -run TestExpandProviders_PgvectorPersistence -v`
4. Run `go test ./pkg/config/... -run 'TestExpandProviders_Pgvector' -v`

**Expected Results**:

- Step 1 prints two matching lines
- Step 2 fails with `expected persistence map, got <nil>`, proving the tests are not vacuous
- Step 3 output contains `--- PASS: TestExpandProviders_PgvectorPersistence` with two subtests
  passing, `derived_id` and `explicit_id`, and
  `--- PASS: TestExpandProviders_PgvectorPersistence_DistinctNamespacesPerInstance`, and ends with
  `ok`. The second test builds two pgvector providers in one CR and fails if they share a
  namespace, which a constant namespace would cause
- Step 4 ends with `ok` and contains no `--- FAIL` lines
