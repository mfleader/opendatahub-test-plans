# TC-E2E-004: Base-config pgvector placeholders resolved from env are unchanged by the fix

**Objective**:

The base config's pgvector entry, using `${env.PGVECTOR_*}` placeholders resolved through
`spec.workload.overrides.env`, still generates an unchanged `vector_io` section and starts the
server after the fix.

**Preconditions**:

- All preconditions of TC-E2E-003
- The base config's pgvector entry uses the starter-sample `${env.PGVECTOR_*}` placeholders for
  `host`, `port`, `db`, `user` and `password`, and carries its own `persistence` block
- Those values reach the container through `spec.workload.overrides.env`
- The PostgreSQL fixture from Section 3.5 is applied

**Test Steps**:

1. Apply the `OGXServer` CR from Test Data
2. Wait 120s for `ConfigGenerated=true` and read the generated ConfigMap name
3. Save `providers.vector_io` from the generated `config.yaml` as `vector-io-post.yaml`, then
   print its `remote::pgvector` entry
4. Save `providers.vector_io` from the base ConfigMap's own `config.yaml` as `vector-io-base.yaml`
   and diff it against `vector-io-post.yaml`, both passed through `yq -P 'sort_keys(..)'`
5. List the server container's environment variable names and filter for the `PGVECTOR_` prefix
6. Wait 300s for the pod labelled `app.kubernetes.io/instance=ogxserver-env-override` to
   reach `Ready`, then count the crash signature in its logs
7. Read the provider ids the operator reports for api `vector_io` under
   `status.distributionConfig.providers`

**Expected Results**:

- Step 3 keeps the unresolved placeholders and the base config's own `persistence` block, with no
  `OGX_PGVECTOR_PASSWORD` reference and no second pgvector entry (Section 8, risk 1). The CR's
  inference provider does replace the base `inference` block, so this case asserts only on
  `vector_io`
- Step 4 prints no differences, so the fix leaves the base config's `vector_io` block untouched
- Step 5 prints the five `PGVECTOR_` variables
- Step 6 prints `0`
- Step 7 lists `pgvector`. The operator fills that field only once the Deployment is ready, so run
  it after step 6

**Test Data**:

The TC-E2E-001 CR with `metadata.name: ogxserver-env-override` and `spec.providers.vectorIo`
replaced by `providers.inference.inline.custom`, one entry with `id: sentence-transformers`,
`type: inline::sentence-transformers` and `settings.trust_remote_code: false`. That makes
`HasDeclarativeConfig()` true so generation runs, needs no endpoint, and leaves the base config's
`vector_io` untouched.
`spec.workload.overrides.env` supplies `PGVECTOR_HOST: postgres`, `PGVECTOR_PORT: "5432"`,
`PGVECTOR_DB: postgres`, `PGVECTOR_USER: postgres`, and `PGVECTOR_PASSWORD` from Secret
`postgres-secret`.
